# AnyWork 桌面与 Web 统一界面设计稿

状态：设计稿 v2，2026-11-11，设计独立核验通过。当前修订范围为桌面控制台、Web 登录、连接与设备入口，以及品牌标志和设备切换入口。Web 对话内容、输入框、审批与工具区域保留 v1 原型，本轮暂不调整。以 Codex 的信息层级和工作方式为参考。本目录仅包含设计文档和使用合成数据的框线原型；产品实现、独立验收与发布进度见[实施任务](../../plan/tasks/ui-refactor-v2.md)。

## v2 修订

| 用户反馈 | 设计处理 |
| --- | --- |
| 标志统一为新的六角形图标 | 两端所有品牌位置直接使用 `web/public/icon.svg`，包括侧栏及更新/托管账号品牌位置；移除 Layers 和方框标志占位 |
| 侧栏设备选择突兀、不整齐 | 连接后改为与导航同轴的单行无框入口：固定图标槽、左对齐设备名、右侧箭头；不再叠加状态第二行 |
| 页面有重复或多余元素 | 未连接设备页不再叠加“我的设备”选择框；登录与托管页使用单列居中布局，去掉空侧栏、无效导航和未登录账号菜单；主标题、状态及空页主动作各保留一处 |
| Web 优先登录、连接、设备 | 保留现有原型对话与输入、审批、工具区，仅处理进入与离开连接的路径及其外层入口 |
| 本地地址不应在面板外另起折叠 | 工作目录、本地地址、复制、首次打开说明与主动作放在同一本地工作区面板中，地址常显 |

减法原则：相关信息放在同一区域；短信息直接显示；只对长内容或低频技术详情保留展开；每个操作与状态确定一个主要位置。首次身份核对、远程中断说明和服务所有权等必要信息继续保留。

## 设计方向与取舍

1. 用“品牌 → 当前电脑 → 当前工作”组织层级。品牌只在侧栏顶部出现一次；账号固定在左下；当前工作标题位于单层内容栏。
2. 主要操作使用中性深色。登录、设备页和工作区共享同一字体、边界和按钮体系；颜色用于状态。
3. 桌面就绪后的首要动作是“打开本地工作区”。Web 的首要动作随阶段变为“登录”“打开工作区”“发送”。
4. 本地地址和首次打开说明直接放入本地工作区面板；身份与诊断等低频长内容按需展开。远程是否开启、是否连接、状态是否可知始终有可见文字，并避免在同一视图重复。
5. 项目和会话只在连接到工作电脑后出现；设备切换保留明确的返回路径，避免把设备目录变成第二套应用。

初步比较过“所有功能留在一张控制台卡片里”和“照搬 Codex 会话列表到桌面”两种结构。前者继续混合准备、访问与维护，后者引入当前桌面没有的会话职责。本稿选择统一外壳、按各端职责配置导航：共享视觉与上下文关系，不强行复制业务菜单。

## 连续用户路径

```text
桌面启动：介绍 → 系统浏览器登录 → 准备/核验本机服务 → 这台电脑
                                                     ├─ 打开本地工作区
                                                     └─ 默认尝试开启远程一次

Web 远程：登录入口 → 托管账号页 → 返回设备列表 → 首次/换钥身份核对
                                                 → 建立加密连接 → 会话工作区
                                                                       └─ 切换电脑 → 设备列表

Web 本机：桌面打开 → 一次性交接 → 同一工作区外壳（本机上下文）
                               └─ 本机授权失效 → 回桌面重新打开
```

## 保留的业务契约

当前启动与默认远程以 [desktop-onboarding-layout.md](../../desktop-onboarding-layout.md) 的 2026-11-11 修订为准；本地浏览器交接以该文及 [desktop-workspace-layout.md](../../desktop-workspace-layout.md) 为准。远程账号与首次身份核对沿用 [account-remote-protocol.md](../../account-remote-protocol.md)。会话、子窗口与编辑沿用 [ui-design.md](../../ui-design.md) 和 [conversation-panels.md](../../conversation-panels.md)。本稿中的新增布局、确认弹窗和导航组织均为待评审设计。

调研时发现的旧文档和文案仍有“需手动开启”描述；最新约定和 `startup.ts` 已采用默认尝试远程。本稿采用后者，实施任务同步对齐相关当前说明；历史图示保留并标明其被取代的范围。

## 后续实施与评审重点

当前评审优先核对六角标志、桌面本地信息是否集中，以及 Web 登录、连接、设备路径是否清楚。Web 对话部分暂不推进重设计。后续实施先落地当前范围的视觉与组件，再核对状态。托管账号页的品牌化需在账号服务侧配置，前端原型无法完成该配置。

需要实际实施验证的重点：本地一次性交接、远程默认一次与手动关闭保持、首次/换钥确认、断线不重发、账号隔离、审批决定、服务所有权和更新空闲检查。原型仅证明设计交互，不代表上述协议或真实连接已验收。
