# Web 登录与设备入口框线稿

状态：设计讨论稿 v2。当前实现入口为 `web/src/AccountApp.tsx` 与 `LocalApp.tsx`。本轮重点为登录、连接与设备，连接后只调整品牌和侧栏设备入口，对话内部保留 v1。视觉与导航见 [shell](shell.md)，历史工作区参考见 [Web 工作区](web-workspace.md)。

## 登录与托管账号页

```text
┌───────────────────────────────────────────────────────────────────┐
│                                                                   │
│                      六角标志 AnyWork                             │
│                                                                   │
│                       登录账号                                    │
│               登录同一账号，连接自己的工作电脑。                  │
│                                                                   │
│                    [登录]  [创建账号]                             │
│                将前往安全账号页面完成登录。                       │
│                                                                   │
│              还没有准备电脑？ [下载桌面端]                        │
│                       帮助 / 语言                                 │
│                                                                   │
└───────────────────────────────────────────────────────────────────┘

登录 → 账号服务托管页 → /app/callback → 同一外壳的设备页
```

登录与托管授权页省去空侧栏、禁用的设备导航及“尚未登录”账号菜单，以同一套品牌、字体和按钮维持连续体验。内容只保留一处六角品牌、一个标题、简短说明、登录/注册、下载帮助和必要授权说明；移除额外欢迎顶栏、大口号与重复的步骤流程。降低设备安装说明的视觉占比，主动作始终清晰。使用现有 Logto OAuth；AnyWork 不新增账号密码输入表单。托管页直接使用现有六角形品牌，通过账号服务支持的品牌配置使用相同字体、中性色和按钮风格；域名与安全边界保持可识别。原型中的托管页是品牌化示意，需要独立服务端配置后才能落地。

回调阶段显示“正在完成登录”，成功后原位置进入设备页；失败有明确重试，不闪现空白或另一套大页眉。语言入口保持同位置；界面文案按中英文覆盖实际状态，避免只有设备页被翻译。

## 设备列表

```text
┌─────────────────────┬───────────────────────────────────────────────┐
│ 六角标志 AnyWork    │ 我的设备                        [刷新] [添加] │
│                     ├───────────────────────────────────────────────┤
│                     │ 选择一台电脑，继续会话与工作。                │
│ 我的设备         ▪  │                                               │
│                     │ 电脑图标  工作电脑        在线                │
│                     │           macOS           [打开工作区] [···]  │
│                     │ ───────────────────────────────────────────── │
│                     │ 电脑图标  家中电脑        离线                │
│                     │           请确认电脑开机并开启远程访问。      │
│                     │                                               │
│                     │ [连接与隐私说明 ▸]                            │
│ 帮助 / 语言         │                                               │
│ 示例账号         ▾  │                                               │
└─────────────────────┴───────────────────────────────────────────────┘
```

设备用紧凑行承载名称、平台、状态和操作；移除一台设备也不形成大面积空卡片。刷新为次动作；添加设备打开引导，不能误导浏览器直接注册宿主电脑。引导说明在 Mac 桌面登录同一账号、本地准备后默认尝试远程、手动关闭可再次开启；支持平台以当前矩阵为准。

设备页不显示电脑选择器；侧栏只保留一次“我的设备”导航，主标题由顶栏承担，内容区不再重复。无设备时只在空状态保留一个添加电脑主按钮，顶栏不再重复添加。连接中只在对应设备行显示进度与取消，不另加重复的进度页面或说明卡。

“···”提供修改名称与移除显示。更名为空不提交，保存中禁止重复动作，配置并发冲突提示刷新。“移除显示”确认明确仅删除目录记录，不能声称远程授权已撤销。新发现但尚未同步身份的记录显示身份待同步，不能开放连接按钮。

## 身份核对与连接

```text
设备行 [打开工作区]
           ↓ 首次或公钥改变
┌─────────────────────────────────────────────┐
│ 确认工作电脑的身份                      [×] │
│ 在电脑端“远程访问 → 本机身份核对”对照公钥。│
│                                             │
│ 设备名称：工作电脑                          │
│ 设备公钥：<完整公开公钥，可选中复制>         │
│ 公钥改变时：重启、重装或更换可能导致变化，  │
│ 请重新核对，不沿用旧确认。                  │
│                      [取消] [确认并连接]    │
└─────────────────────────────────────────────┘
           ↓
同一外壳主区：正在连接工作电脑… [取消连接]
           ↓ 握手验证成功
同一外壳：侧栏无框单行显示工作电脑，填入实际项目与会话导航
```

在线只表示发现状态，打开仍要求实际协议与端口就绪。首次或换钥绝不通过布局优化跳过确认；已经核对且公钥相同沿用现有信任记录规则。连接中可取消；取消、切号、授权过期后迟到结果不能打开旧工作区。

连接后，设备入口采用与“新会话 / 搜索会话”相同的左侧图标槽和文字基线，名称左对齐、箭头靠右；不包白底卡片或常驻边框，不再显示“已连接 · 加密传输”第二行。连接状态保留在现有工作区顶栏一处。设备名过长可截断但完整名称仍可读取。

入口菜单中的“我的设备 / 切换电脑”在连接后始终可达。离开时说明会断开本页连接与终端，而电脑上的 Agent 工作继续；连接仍按现有 owner/transport 清理规则隔离。

## 本机浏览器入口

```text
这台电脑 · 本机浏览器
  正在建立本机会话…
  或：本机会话尚未建立 / 已到期
  请在 AnyWork 桌面端点击“打开本地工作区”。
  [重新检查]                  [登录查看远程设备]

建立后：同一工作区，侧栏上下文为“这台电脑 / 本机浏览器”
  账号菜单改为“本机网页会话”
  可展开：由 <来源名称> 在本机打开（打开时快照）
  [退出本机网页会话]
```

本地入口不把来源快照当成 Web 已登录账号。ticket/cookie 沿用原规则；ticket 不显示在页面或复制地址。刷新有有效 cookie 可恢复；失效不能通过账号登录代替本机会话，仍应回桌面安全打开。退出本机 Web 仅结束该 cookie 会话及其 PTY，不退出桌面账号或关闭远程。

## 状态变体

| 状态 | 布局与动作 |
| --- | --- |
| 账号/目录读取中 | 同外壳骨架与“正在读取”；不抢先渲染零设备 |
| 无设备 | “添加第一台工作电脑”与安装步骤；不展示空白会话导航 |
| 目录失败/未知 | 明确“设备状态暂不可用”与刷新；不把缓存记录当在线 |
| 离线 | 展示上次已知目录记录，打开禁用，提示检查开机联网 |
| 在线但安全连接未就绪 | 单独说明，不把在线当作可打开 |
| 连接失败 | 回到同一设备上下文，简短原因与重试 |
| 授权到期 | 结束旧连接，提供重新登录/连接路径；不自动重复业务写入 |
| 平台不支持 | 说明当前桌面账号宿主限制，不展示没有依据的可用承诺 |

弹窗的焦点、取消、Escape 与窄屏遵循统一外壳规范。设备页在 390px 下将动作排到名称下方；公钥和路径换行，不能横向撑开页面。

## 组件与实现关系

建议 `WebShell` 贯穿 `SignInPage`、`DevicesPage`、`ConnectionGate` 和 `WorkspaceContent`，由 `AccountHome` 继续持有账号、目录、连接和取消控制器。`HostedAuthBoundary` 只是页面交接状态，不接管密码处理；`LocalEntryGate` 独立持有本机会话。视觉组件共享不意味着 OAuth、local cookie 或远程 transport 可以共享授权。
