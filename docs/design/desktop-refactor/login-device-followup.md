## 浏览器登录复用

客户端继续用系统默认浏览器和独立 Native PKCE 授权。普通登录去掉强制 `prompt=login`，保留获取 offline_access 所需的 consent；有效的同 issuer 浏览器 SSO cookie 可免再次输入密码，可能仍需确认授权。不能复制 Web access/refresh token、导入 Cookie 或绕过账号验证。不同浏览器/profile、无有效 provider cookie 或 provider 安全策略仍可能需要认证。登录失败/取消不留下可重试的未知 refresh grant，不改变默认远程一次和手动关闭意图。

账号显示优先使用可信已验证 profile 的 name/username，再用邮箱。现有 Account API 返回字段需按实际结构核对；若缺少个人资料可使用已验证的 OIDC profile/UserInfo。缺失时明确显示“已登录账号”，不暴露 subject/ID；原 subject 仍是身份边界，不因展示名相同而合并身份。

## 设备名称

- 每个客户端安装首次使用时生成可读且可区分的名称（例如 `Mac · AB12`），持久保存；不使用账号 ID，也不默认泄露用户目录或完整机器主机名。重启、登录或重新发布不重新生成名称。
- 桌面工作区提供设备名称与编辑入口；保存、取消、错误反馈明确，输入 trim 后为 1–80 UTF-16 单元，无控制字符；中文和 Unicode 名称有效。
- Native 持有持久化与账号目录更新，UI 不保存授权资料。账号已存在的设备名称（包括 Web 重命名）优先保留，禁止默认名覆盖已改名称。客户端编辑成功后目录 label 与本地显示一致；网络失败不假报已同步，明确保留可重试草稿/状态。
- 改名不改变 installationId、publicKey、keyVersion、账号归属或连接授权，不关闭远程连接、不重启本地服务；更新目录时保持其他账号字段、偏好和设备记录，保留既有容量/版本/读取核对与串行 token owner 约束。

## 核验

真实组件和 Native 调用链分别验收：Web dialog 实际浏览器坐标；Native loopback 回调实际 HTTP 页面与无效 state；SDK 真实授权 URL 的 prompt/PKCE/consent；可信资料映射与缺失资料；设备名首次生成、磁盘重载、目录改名/错误/其他字段保留；macOS 实际原生窗口交通灯与可拖动区。合成边界不冒充真实账号 SSO 或实装更新。源码提交后独立审查，通过后集成测试与现有发行流程。
