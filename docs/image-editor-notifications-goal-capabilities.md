# 输入图片批注、会话提醒与目标能力检查

2026-11-06。

## 图片编辑

输入框中的图片继续使用现有图片查看器。点击缩略图后，通过顶部「编辑图片」进入编辑画布，支持文字批注（含中文、多行）、画笔、直线、箭头、颜色、线宽、字号、缩放及移动。完成后在浏览器中按原始图片坐标合成 PNG，上传为一个新的会话附件并替换输入框中的路径。原始文件不会被覆盖。

附件保存原始图片和矢量操作历史以及历史游标。保存、关闭、再次进入编辑器都不会丢弃原图或重做分支。撤销后添加新操作才会截断重做分支。取消编辑丢弃本次未完成的修改。记录保留于当前页面的当前输入附件中，发送、移除附件、切换会话或刷新页面之后不提供编辑历史恢复；发送后的历史图片仍为只读预览。主会话和子 Agent 输入框共用实现。

保存中禁用消息发送；失败留在编辑器中，可重试。切换会话会中止旧上传，迟到响应不能修改新会话的草稿。输出限制与原有上传保持一致，PNG 最大 20 MiB；编辑画布限制 4000 万像素，避免大图耗尽浏览器内存。手机使用自然坐标映射和触摸指针绘制，缩放后可用移动工具平移。

## 会话通知

通知订阅来自既有会话缓存的全局认证事件流，不新建会话，也不为通知单独读取全部历史。执行完成、失败、权限申请和用户确认请求产生网页内提醒、通知角标及网页标题未读数；点击跳转到原会话。现有待处理请求加载后可恢复提醒，旧完成历史不会重放为新通知。请求在桌面或其他客户端处理后自动标记已处理并清除待处理提醒。

右上角铃铛提供通知中心、全部已读、单条查看及系统通知开关。浮层可通过外部点击、Escape 和关闭按钮收起。当前会话已有待处理请求时让出浮动提醒区域，以免遮挡权限卡片；通知中心及角标继续保留。系统通知只在网页后台或窗口失焦且用户已授权时显示，优先使用 Service Worker，桌面环境可回退 Notification 构造器。点击系统通知可唤起网页并切换对应会话。拒绝权限不影响网页内提醒。

浮动提醒是否让出区域，以当前会话实际加载的待处理请求为准，不能仅依赖通知账本。历史页与全局事件流可能交错到达：较早 turn 的完成事件不能将较新 turn 的待处理请求标记为已处理。只有稳定 turn 身份匹配时，才可从 turn 完成推导该 turn 请求结束；缺少身份时不得跨 turn 推断，仍接受明确的请求解决或插件退出等既有权威信号。已读、去重和通知中心显示不能替代待处理请求的真实状态。

当前版本不是服务器 Push 服务。系统通知需要 HTTPS 或 localhost、浏览器支持及系统允许；网页关闭、设备休眠或浏览器挂起连接时不能保证提醒送达。通知正文只包含会话标题，不附带命令或权限请求中的敏感内容。通知列表保留于当前页面内存，不跨刷新保存。

## 目标报错：发送前判断实际能力

报错的根因仍是运行中的独立桌面 stdio 引擎与会话跟随协议之间的能力差异。消息提交先成功，之后 AnyWork 尝试通过不支持的目标设置路径，形成「消息已发送，但启用目标未确认」。修复在消息送达、进入排队及目标操作前检查实际传输能力，明确不支持时直接拒绝，保留文字、目标标记和附件，不能把普通消息成功当作目标成功。

`GET /composer` 新增 `goal_capabilities`：create、edit、resume、clear、pause 和 reason。原桌面 follower 连接只声明读取与暂停；未连接时不宣布可写；直接共享引擎维持完整目标 API。界面在新建菜单说明原因，恢复和删除按钮按能力禁用；正文可查看，编辑器明确解释保存限制，快捷键也受相同限制。已恢复的目标模式草稿不允许通过 Enter 或按钮绕过限制。服务端再次检查，不信任浏览器能力状态。

**这项修复没有实现当前独立 stdio 桌面的目标新建、恢复、编辑和删除。** 使用现有 `scripts/desktop-bridge.py` 在退出桌面后的共享引擎启动路径，才有可直接发送目标 RPC 的引擎入口。已有 stdio 进程不能通过改变启动环境转换；本轮没有停止、注入或重启该进程，没有更改 ChatGPT.app，也没有发消息或操作真实目标来验证。

本轮通过 REA 只读复核原包：app.asar SHA-256 `5ddc4e48259aa6f979e04529b1a5a4ae54b0f5c4ad6db5c6e004924c10916ddb`；限定模块 `.vite/build/src-DsLVGakC.js` SHA-256 `28a0918f01c50b0eb17676e894998ad7182f119d978adf0467ccaac3583f259c`，Evidence `ev_9a27f0002ba950a737239a8e91724c8486f21133167c6c1c757d806f76581319`，摘要 `ev_8a675c6e35295225f9ba8d637e1e8f202639efd36760c2dd37eef6d5358331a1`。观察到 manager 直接发送 thread/goal/set、thread/goal/clear，follower 注册表没有对应目标写方法。静态语义图达到配置容量，未选模块及动态入口不能据此证明全部不存在。原包若干 unpacked 原生文件与归档声明哈希不同，以 record-and-continue 记录；没有执行那些文件或将其完整性当作已验证。提取内容及 REA 缓存不进入公开源码归档。

## 验证入口

- `web/src/imageAnnotations.test.ts`：历史分支、原图保留、坐标、绘图与导出共用渲染器。
- `web/src/sessionNotifications.test.ts`：事件分类、重复事件身份、请求 ID 类型和跨客户端处理。
- `e2e/image-editor.spec.ts`：桌面/手机真实上传、像素检查、发送路径、图库独立、取消、重试、触摸以及切会话时中止。
- `e2e/notifications.spec.ts`：真实隔离会话事件；系统通知接口模拟，覆盖后台、授权拒绝、点击切换、重复抑制和已处理状态。不是操作系统通知面板实机验收。
- `e2e/goal-capabilities.spec.ts`：受限连接的草稿与附件保留、按钮/快捷键边界、可读目标与暂停。
- `scripts/desktop-host-http-test.py`：隔离 framed desktop host 验证目标消息及排队在发送前被拒绝，无原 owner 写入，暂停仍等原快照确认。
