# WorkBuddy persisted local history

AnyWork reads the selected native WorkBuddy profile passively, independently of the live desktop control carrier. It never creates a conversation, resumes an engine, writes the native database or reads account/credential records to list or open history.

Profile resolution is `ANYWORK_WORKBUDDY_HOME` (absolute explicit root), then the validated launch descriptor's `configDir`, then the current OS user's `~/.workbuddy`. An explicitly configured invalid descriptor fails instead of switching to a different default profile. A valid stale descriptor retains its profile even if its process is closed. The local OS profile includes local rows from previous account partitions; this is deliberately not a claim that the reader identifies the current signed-in account.

The pinned WorkBuddy 5.9.3 format uses `workbuddy.db` table `sessions` for metadata and `projects/<native cwd key>/<conversation id>.jsonl` for body records. Known owner directories and ACP alias sidecars are supported within that profile. Local, nondeleted root rows are imported; native quick-ask hidden rows are excluded, archive state is preserved. Cloud/remote transport is excluded and cannot be routed to local execution.

Catalog scans read only selected conversation columns. Bodies load lazily and preserve native request IDs (`conversationRequestId`, or the original user record ID in older transcripts), tool-call IDs, text/reasoning/tool output and the active resend branch. The existing live projection produces the same event identities, so switching from persisted to live history does not replay commands. Disk metadata does not infer running state or overwrite an attached runtime. Complete unchanged transcripts reconcile only previously disk-imported branch events; live/pending events remain intact and clients receive `history/reset`. Torn final records retain their valid prefix with `history_notice`; malformed complete records and unresolved native fork/parent chains retain an existing cached body with an explicit notice. Unresolved branch chains cannot be treated as authoritative empty history for pruning.

Reads are bounded (128 MiB transcript/catalog, 16 MiB line, 200,000 records, 10,000 metadata rows), reject symlinks and path traversal, require the current Unix user's native root and use SQLite read-only/query-only access. Revision caching avoids reparsing the same body on every page. Supported layouts are version bound; unknown schemas fail visibly rather than inventing transcript content.

`--agent-scope all` / `ANYWORK_AGENT_SCOPE=all` explicitly enables all-project histories for Codex, dsh and WorkBuddy. Default `workspace` restricts external rows to the configured project. Legacy `--codex-scope all` still applies only to Codex. Desktop-managed service launch opts into the generic scope. A deleted historical cwd remains readable in all-project mode; file operations retain their own canonical path checks.

When the host is unavailable, history, deferred tool details and safe model/composer reads remain available. Composer/models report `settings_available:false`; connect reports history mode. Mutations still require the original native host and never launch a second execution engine.

## Evidence and acceptance

Static REA inspection of the privately retained 5.9.3 extraction selected the shipped `main/node.js` and `main/conversations.js` modules. Evidence parent `ev_3ba2cbf0966ecccb2a4e1e2fd3f32ecff544fd1d1710d3dc23b42d8b7262b7d0`, summary `ev_550ff007aed74a419f0f994904463c614f62476147c042436ef7755d36a1cbb6`; extraction SHA-256 `607a9114759019e892c18763789f6ab26f5bbf0c81bb5102648227ce09a74ea7`. No native product files are shipped with AnyWork. The observed storage-key/replay reducer, LocalConversationHistorySource filters, transcript request grouping and ACP alias resolution guided this implementation.

Explicit read-only aggregate acceptance on the installed profile found **8 local metadata rows, 8 transcript files, 20 projected turns and 207 normalized events**, all with cwd outside the AnyWork project. No conversation text, account IDs or credentials were printed. This confirms installed-history read coverage; it does not replace the separate native writing/collaboration acceptance contract.

Isolated tests cover account-partition metadata, hidden/deleted/remote rows, native identity, active branches, malformed/torn data, tool detail expansion, directory scope, restart/idempotence and both desktop/mobile history rendering with unavailable SSE/control. Run `python3 scripts/shared-history-test.py` after building the server. The optional installed-profile unit test requires an explicit `ANYWORK_TEST_WORKBUDDY_HISTORY_ROOT` and `--ignored`; ordinary tests never inspect native profiles.
