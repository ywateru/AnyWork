# 新账号设备发现、连接过期与图片故障调查

用户报告的环境为自部署 Logto、Vercel Web `/app/`、CyberGrid 协调，以及本机新编译的 Native 客户端。调查不读取用户新账号的令牌、设备目录或业务内容；协议测试使用隔离夹具。

## 已确认的原因

| 现象 | 证据与影响 | 修正方向 |
| --- | --- | --- |
| 已连接工作区频繁提示授权过期 | 原协议将连接寿命限制为 `min(JWT exp, now+300s)`，未实现续期。当前资源 JWT 本身也只有300秒，Logto SDK还可能返回尚未过期但剩余时间很短的缓存令牌。 | 初次连接强制取得新令牌；在原 Noise 通道内提前重新验证同一账号的新授权，收到有效确认后才延长连接。 |
| `/agents/codex-light.png` 无法显示 | 公开访问根路径返回404，`/app/agents/codex-light.png` 返回200及正确PNG。组件硬编码根路径，而Web部署在 `/app/`。 | 组件使用Vite部署base，同时在同一个受检静态产物中提供根路径图片别名。 |
| 长连接的后续隐患 | 浏览器与网关分别把请求ID总数限制为1024，正常轮询即可逐渐耗尽。 | 产品生成的规范递增 `rN` ID采用常数空间高水位检查；保留任意旧式ID的有限防重放集合及并发限制。 |

## 配置失败的证据边界

当前公开 Grid 健康检查和 Native 应用配置均成功，issuer、client与resource绑定吻合，不能据此证明用户此前的失败是永久配置错误。过去公开请求曾出现连接重置；原实现的单次配置GET把网络失败与内容不符都归入 `REMOTE_ENABLE_GRID_CONFIG`，因此暂时网络/服务失败是有证据支持的解释，但未获得用户当时请求的完整轨迹。

配置验证失败时，Native不会向Logto发布可连接的设备记录。这样避免Web显示无法使用的设备，也解释了首次开启失败时新账号在Web看不到设备。Web目录轮询周期为20秒。后续验证/注册/暴露成功后才发布目录。

修正仅对幂等配置GET有限重试，区分固定的服务不可用诊断与绑定错误诊断。实际绑定不符仍立即失败；不自动重试OAuth轮换、注册或端口暴露。SDK注册过程内部再次读取配置仍可能失败，不能用重复注册掩盖。
