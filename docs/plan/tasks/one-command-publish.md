# One-command publication

User request: a single reusable script must publish the current project and refresh the download website without a person repeatedly running/checking each stage. Implement a Python-standard-library entry point `python3 scripts/publish.py` plus `npm run release`; do not trigger a real new release while developing this automation.

Default contract:

- Require a clean committed main checkout and the expected ywateru/AnyWork origin. Do not stage arbitrary source, private files or signing material. Read authentication from GH_TOKEN/GITHUB_TOKEN or ~/.ssh/ghp, optionally an explicit token file; never log/store credentials or put them in command arguments. No dependency on /tmp wrappers or gh installation.
- Increment all embedded versions and Android code once (patch default, minor/major supported), using the existing version machinery. Update only the current release-note heading automatically; retain the authored bilingual release notes. Pin the prepared source commit and never reuse/move a tag or overwrite a release. Check reserved tags as well as published versions.
- Push main, wait for the exact source SHA's successful Checks workflow, then push its annotated version tag, wait for the complete release matrix and publication, and wait for/update Pages. Never equate a completed job with success. Fail closed on failed/cancelled workflows and show their public URLs.
- Persist atomic resumable state under Git's private common directory, with a process lock. Interruption or an ambiguous push/dispatch must not double-bump, double-publish or dispatch duplicate workflows. A repeated call resumes unfinished work; after completion with unchanged source it is a no-op. New source changes start a new version. Reject unsafe checkout/remote changes rather than publishing a different snapshot. Expose explicit failed-job retry, status, verify-existing-release and read-only dry-run modes as useful; no manual polling is required.
- Run the existing heavy CI gates once for the pinned SHA, without local rebuilds/repeated full suites or the optional large live-upgrade download. Reuse successful exact-SHA checks on resume. Bound waits and transient network retries, preserve state and return actionable nonzero exit on real failures.
- Automatically validate release tag/commit, expected 20 nonempty assets, all 19 checksum entries against GitHub digests, five version-bound updater signatures, installer HEAD availability and Pages release.json plus embedded EN/ZH version/download links. Preserve immutable assets. Light metadata verification is appropriate; do not redownload all installers. Website must not silently remain on an older release. A finished report records public URLs and completed gates, excluding secrets.
- Provide concise bilingual usage/recovery documentation; distinguish dirty-tree/source fixes, failed native checks, publication and Pages-only retry. Existing manual workflows may remain, but the new recommended path must not bypass Checks.

Development owns scripts/publish.py, focused deterministic tests, package.json entry and (if necessary) minimal CI integration for the focused test. Root owns release documentation, orchestration and merged checks. Independent verifier reviews exact source and tests interruption/resume, SHA binding, immutable tags, API/network/error behavior and credential handling. All tests use temporary Git repositories/mocked GitHub endpoints; no actual publication, version bump in the real checkout, service restart, native prompt or installer launch.

Status: implementing; source-only delivery, no new release requested.
