## Implementation review gates and limits

No new scope requirement is added by this review. Before coding, the module document must select the concrete qualified bridge seam or explicit unsupported outcome required by task line 32. A callback invoked at bridge enqueue, an optional qualifier field ignored by old consumers, or silently calling raw `send/call` would fail that existing requirement. A synthetic qualified consumer may prove the new seam internally, but cannot prove unchanged production adapters migrated.

The exact source candidate will need independent barrier-based evidence for revoke-before/while-queued/before-admission/after-admission ordering, wire/invoke counts, partial writes, terminal wakeups with full queues, canceled pending registration cleanup, byte/count release, repeated close and owned versus external teardown. Successful SDK tests alone will not close B/C's initial imports, same-Arc peers, event/Store/media effects, automatic responses or durable creation/preparation gates. Legacy behavior must compile and retain its existing semantics while remaining visibly unqualified.

No source implementation exists in this review scope, so final writer atomicity, pending-call cancellation safety, cleanup budgets, receipt limits and lint annotations are not accepted as implemented. Existing raw transport safety is not upgraded by this task PASS. Native-positive capabilities remain denied; complete I07, I02/I03, real account/platform acceptance, release and Web activation remain open under their own contracts.
