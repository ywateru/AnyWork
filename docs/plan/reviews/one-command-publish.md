## Findings

- **P2, blocking, resolved:** A valid fetch origin did not establish a safe push destination. The final implementation validates all effective fetch and push URLs, including Git URL rewrites and multiple push URLs, before preparation or publication. Credential-bearing and unrelated destinations are rejected.
- **P2, blocking, resolved:** Recovery could discard index-only edits through `reset --hard`. A separate temporary-repository probe reproduced loss of a staged README edit in the initial draft. The final candidate checks both complete worktree and staged changed-path sets, permits only known preparation files, and verifies their allowed bytes, index modes, worktree executable modes and regular-file types. The regression retains staged data, and symlink/mode edits remain intact.
- **P2, blocking, resolved:** A malformed environment token containing a newline reached urllib's header validation, whose `ValueError` included the credential. The final constructor rejects invalid token characters with a fixed message. Generic error handling does not echo arbitrary lower-level exception text. Environment/file-token regressions use synthetic credentials; public downloads carry no API authorization, and authenticated API redirects are disabled.
- **P2, blocking, resolved:** A tag-push interruption must not skip publishing the pinned tag or abandon an unresolved publication. The release phase now reconciles the tag before waiting. `--new` refuses unresolved tag pushes and active release runs. The final follow-up also requires a durably requested release retry to appear as a newer attempt before retiring the previous operation, including an accepted POST whose response was lost.
- **P2, blocking, resolved:** Matching website metadata length alone admitted duplicate entries. The final verifier requires the exact unique asset-name set. Signature-file/version, target and URL corruption are rejected after recomputing fixture digests, so those tests exercise semantic validation rather than stopping at an earlier checksum mismatch.
- **No open blocking findings:** The implementation and imported project helpers use the Python standard library. Git is the only required external command; neither `gh` nor private temporary wrappers are invoked. Network Git commands are bounded and their process groups are cleaned up after timeout/interruption. State replacement is atomic, uses private modes and fsyncs file plus directory on POSIX. Workflow gates require exact workflow identity, SHA, branch and a successful conclusion. Successful exact-source gates are reusable; failed/cancelled runs do not authorize a tag. Existing tags and assets are never moved or overwritten.

## Conclusion and limits

**Pass for merge; no open blocking or nonblocking source findings.** The orchestrator should run the merged focused suite and normal source/version/export checks. This is a source-only delivery for future publication and does not authorize a new release during verification.

The light verifier establishes metadata/digest consistency, five signature-file/version bindings and published website metadata. It does not perform binary signature verification or installed-upgrade acceptance without downloading and installing the packages. Windows lock/process handling was reviewed but not executed on this macOS host; the standard library does not provide directory fsync on Windows. An ambiguous mutation intentionally remains fail-closed until its remote result becomes observable rather than blindly resubmitting it. The bilingual documentation accurately preserves these recovery and verification limits.
