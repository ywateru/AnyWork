## Nonblocking implementation notes

### N1 / P2: keep response gate waits off the normal event-consumption path

Locations: [contract lines 119–120](../../runtime-lifecycle.md#lock-order-and-qualified-effect-commit), caller row at line 203, and the command/event-progress acceptance case.

The intended invariant is sufficient, but merely dropping the cell/Store guards and then awaiting `app.gate` **inline in the one normal consumer** would still stop all later event commits. The existing shape at `runtime.rs:201–205` must not survive that way. The implementation should use a bounded response-intent actor/task or equivalent scheduling that lets the normal event/closure path continue, while the eventual response separately obtains the gate and revalidates the exact occurrence. This is a clarification of the already stated no-gate-wait event invariant, not a new durable response ledger or a new source-design blocker. The prescribed barrier-based command-holds-gate test must enqueue a pending request followed by a required completion/closure and assert the latter is consumed without releasing the command gate first.

### N2 / P2: preserve explicit queue origin independently of native Start/Steer

Locations: contract caller rows at lines 194/198 and coordinated I02 delivery at lines 212–226.

Static source distinguishes worker auto-send (`api.rs:1084–1117`) from an explicit selected-row action (`api.rs:1032–1036`). The selected-row path does not require the queue to be unpaused; at `api.rs:519–541`, the resulting native method can be Start when idle or Steer when active. Consequently a future QualifiedCall must carry/consume I02's actual typed dispatch origin and guards, rather than deriving worker/manual authority from native method or Route alone. Editing-head/FIFO and paused/manual rules remain I02-owned and are being clarified separately after the ledger review. The lifecycle contract's preservation and serial-integration requirements are consistent with that distinction; no independent lifecycle queue policy or second dispatch qualification should be introduced.

No contradictory requirement was found in the proposed lock partial order, setup linearization/cancellation, across-await writer fencing, attach-time effect coverage, same-Arc peer validation, bounded terminal observations or I02/I03 dependency separation. The two P2 notes above guide source implementation and test specificity; neither permits a partial connected migration to be advertised as safe.

The real fake-transport/actor/HTTP negative matrix, exact source review and merged checks must pass before connected acceptance.
