# 账号远程可靠性独立复核

日期：2026-11-10。结论：接受配置/图片提交 `a362008` 与连接续期提交 `6e624bb` + `35b19f5`，无剩余阻断项；这些修订留在隔离分支，未发布。复核基础为 `92db217`。复核只使用公开端点及本地隔离夹具，没有读取真实用户 grant、设备目录或工作区，没有更新运行中的客户端、服务或部署。

## 根因与证据边界

- 正式站点 `/agents/codex-light.png` 返回404，而 `/app/agents/codex-light.png` 返回200、PNG且长度8353字节。AgentIcon 原来固定使用根路径，和正式 `/app/` base 不符；内联 SVG 图标不依赖该图片请求。
- 原协议在 JWT 验证、网关和浏览器三层都将单次授权限制为最多300秒，没有续期。这是正常操作到期离开工作区的确定源码原因。资源 JWT 本身也为300秒；保持短授权并重新验证比单纯延长到期时间更符合既有安全边界。
- 公开 Grid 配置探测返回200，issuer/resource/Native client 与公开客户端配置一致。原 `GRID_CONFIG` 同时表示网络请求失败和严格绑定不符。用户重试后成功与暂时故障一致，但没有足够历史证据断言具体一次故障源自 DNS、TLS 或某个 HTTP 状态。
- 登录本身不发布设备。Native 必须成功完成显式远程开启与 Logto 公共设备索引发布，Web 才能在后续20秒刷新中识别设备；不能据此断言所有看不到设备都由配置 GET 引起。

## 配置和图片复核

`a362008` 可接受。重试范围仅为公开、无 Authorization 的幂等配置 GET；三次各最多8秒，延迟250/750毫秒，最多25秒。确定的 schema、绑定、认证或不存在错误立即失败；临时传输及限定 HTTP 状态耗尽后返回独立固定错误码，不泄露原始 URL/正文。SDK 在登记内部可能重新获取配置，当前修订没有盲目重放登记或 OAuth 交换。

图片使用 Vite BASE_URL；Vercel 组装器同时保留 `/app/agents/` 与根 `/agents/` 的同一公开静态字节，不依赖放宽 CSP。独立运行了实际 SDK loopback 配置夹具3项、Agent 图片测试3项、静态组装测试7项、Native UI 构建，均通过。首次全新工作树 Rust 检查仅因缺少 Tauri frontendDist 失败；完成 UI 构建后同一命令通过。

## 连接续期复核

初版 `6e624bb` 的严格 owner/issuer/audience/client/scope/exp/nbf 复用、旧授权截止前验证及 ACK、SDK 公共 API 与跨 resource 单一刷新队列、退出 fencing、浏览器双时钟与晚响应拒绝符合设计。没有业务写入重放。固定240秒 HTTP 操作预算不再因旧授权边界提前取消，续期也不延长其操作预算。单调 `rN` high-water 替代永久1024业务 ID 总量限制，legacy ID 保留有界兼容集合。

独立审查提出的三项问题均已在 `35b19f5` 修正：外层只将关闭/授权截止设为优先，完成/输出/入站消息采用内层公平选择，避免活跃输出使续期饥饿；拒绝测试明确断言关闭且禁止 Binary ACK；未确认的退休上传 ACK 集合在1024项时失败关闭。授权截止改用精确 Unix 到期差值，避免整数秒取整额外延长授权。

在精确最终源码上独立运行 Rust 协议3项、网关7项、Web 授权/调度/配置15项，均通过。另以专用 loopback Vite 端口、独立 Chrome 和 Rust 隔离服务运行真实互通脚本，27项断言通过，覆盖两次固定绝对到期的不同令牌、原 HTTP 跨旧授权截止完成、同一 PTY 在第二次续期后回显、错误续期中止活跃 HTTP/浏览器 PTY 与实际本地 PTY socket，以及原有二进制/20MiB/multipart/取消/密文/重放拒绝。夹具与本任务启动的 Vite 随后退出。

该证据不等于真实账号新授权、正式产物发布、物理手机切网或30分钟/8小时稳定性验收；这些仍是后续发布/整合门槛。最终检查没有使用真实账号，未安装候选客户端，也未改变任何现有用户通道。

## 后续统一登录的责任边界

移除 AnyWork 用户界面的匿名、固定隧道和 WireGuard 选项属于产品整合，不是 CyberGrid 当前缺少这些选项。源码固定的 CyberGrid 已有可信配置、同账号设备发现、单飞协调恢复、65秒 lease、epoch/登记 fencing、事件和主动申报端口 URL。反馈应请求可组合、可测试的浏览器安全连接能力与可用性语义，而非把现有能力列为全新需求。

JS SDK 当前明确只读，不实现 Native 的 WebRTC/iroh/mTLS 字节流。设备级 tunnelUrl 不能直接作为浏览器业务 HTTP URL；当前 Web 业务依赖 AnyWork 自有 Noise/JWT 网关。若后续由 CyberGrid 接管，必须明确端到端密钥、短授权续期、取消/退出/换账号、手机浏览器休眠恢复和能力版本协商，不能用普通 HTTPS 转发替代业务端到端加密。

本地 Web 与远程 Web 可共享产品界面，但本地管理 bearer 与云登录身份仍是不同授权边界。不能把本地管理 bearer 发布到目录。要求运行期设备 refresh token/私钥仅在端点 RAM，不能混同于“协调服务没有任何持久秘密”：当前 Redis namespace seed 与登记 fence 确实持久存在；其用途、清理/备份边界应明确。业务正文、文件、终端字节和解密密钥继续不进入云端业务存储。
