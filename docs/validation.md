## 未打开会话的执行状态与慢宿主快照限制

2026-11-05：发布后端修复，Web 资源沿用 `anywork-32f3197c3fba05f7`。后端二进制 SHA-256 为 `cb400d22784c0405ec62d40ff07182527a307035e7eb558a165c26caf32ca0fa`。

原先只有建立控制 runtime 的会话会收到桌面执行状态，其余侧栏条目依赖历史索引，无法把独立查询进程的 notLoaded 解释为原宿主的运行状态。新增独立只读观察器订阅目录范围内已发现的外部会话，未选择会话也能更新执行、等待回应、空闲和下一轮开始的状态。缓存有有效期，不改历史排序时间；owner、连接或 revision 异常会失效并重新同步。原桌面恢复中和未确认提交也会显示活动状态，真实待回应请求补齐等待标记。

原控制适配器每秒索取完整快照时没有检查上一份是否已返回。现在控制连接与侧栏连接都限制最多一份快照请求在等待，持续收到更新时侧栏不重复索取快照；超时、退出和取消订阅有明确清理。

最终发布程序通过 Rust74项（服务端66、适配器5、SDK bridge3），格式、Clippy及debug/release构建通过；桌面宿主HTTP15项、通用HTTP25项、发现HTTP9项、共享控制HTTP10项，共59项通过。新增6项HTTP用例覆盖未打开的多个线程、执行/等待/空闲/下一轮、身份与revision异常、断线重连、无回应过期，以及宿主变慢时快照请求不积压。桌面/手机侧栏浏览器专项2场景通过，增加未打开的未知会话变为运行中的断言，没有增加连接或发送。源码归档边界3项通过。本轮没有重跑全量Web单元与全部浏览器套件。

慢快照候选的15项首跑14通过、1项在恢复无回应宿主时失败：一份尚未返回的请求按新规则需要等待超时，旧测试只等待6秒。恢复等待改为16秒，以覆盖12秒观察有效期后的重新发现；最终release完整15项通过，没有放宽状态有效期或允许并发快照请求。

发布只重启AnyWork，令牌、Web资源和原桌面进程启动时间核对保持。实机只读核对发现桌面宿主初始化/owner查询超时，当前真实列表状态仍为未知；共享引擎另行查询成功，但当前会话为notLoaded，loaded列表为空，不能作为原桌面已空闲的证据。原桌面主进程观察到高CPU及内存占用，一秒只读采样未建立具体JavaScript函数归因；不能把负载原因直接归给AnyWork。原应用未修改、重启或注入。当前真实桌面的全部运行标记尚未验收通过，不能以隔离用例替代；入口恢复后由观察器自动重连。

## 侧栏按钮互斥、发送反馈与具体执行状态

侧栏展开时，会话顶栏的“会话列表”按钮隐藏，仅侧栏保留“收起侧栏”；收起后显示“会话列表”，再次展开则隐藏。手机抽屉打开时隐藏背景中的打开按钮，保留抽屉关闭入口。

发送复用已确认的原会话连接，普通提交不再先等待单独的状态读取。服务端在同一会话操作锁内按当前执行状态决定是否排队，避免前端状态过时导致误引导或无谓排队。点击后立即显示“正在提交消息…”及旋转图标；接收结果直接更新队列和恢复输入，不等待会话列表/目录刷新。原会话接收后唤醒历史刷新，前台外部会话轮询间隔从5秒改为1秒，后台保留5秒。模型及输入器设置的只读目录查询释放会话操作锁，避免慢模型服务阻塞发送；操作写入仍保留互斥与不确定结果保护。

工作提示只读取当前进行中回合，区分思考、生成回复、读取/列出/搜索文件、搜索网页、执行命令、修改文件和调用工具；并发工具显示额外任务数。无具体活动证据时显示“正在处理你的请求…”，不从旧回合推断状态。

验证：Rust73项、Web251项、格式/类型/Clippy及debug/release构建通过。通用HTTP25项、桌面宿主HTTP9项、共享控制HTTP10项通过；新增服务端状态与过时客户端意图的双向竞争测试，以及阻塞模型读取时仍能在原回合发送的并发检查。桌面/手机专项8场景及完整session-access/queue-goal60场景，共68场景通过（两次顺序执行）。专项故意挂起会话/队列刷新，确认消息仍可提交、返回的排队条目立刻显示、输入框恢复可编辑；未宣称固定毫秒级延迟或网络超时不存在。没有重跑完整历史浏览器套件。

队列编辑恢复本项目已有文字、富文本文档和附件，未覆盖原版全部评论、应用截图、MCP、演示建议等上下文字段；撤销入口为AnyWork显式按钮，未接入完整应用撤销/重做栈；编辑中的普通提交和反向快捷键都恢复原FIFO位置，按本次复核的原生queue override实现；此前将编辑态直接引导列为缺口的判断已纠正。空输入队首引导、↑取回队尾及后续主输入历史轮换已接入；后台/opening prompt的first插入、旧引用lexer全部边界、原生admission呈现时序和recourse/Aeon/goal-continuation特化仍有差异。目标正文已改为原生式分屏编辑标签，支持还原、保存、保存快捷键、更新时间与手机覆盖面板，保存后保持打开并恢复active状态；超过4000个Unicode标量的目标使用受控本地附件文件引用。发送者包装、automation/heartbeat/delegation/goal/appshot等其他特化呈现仍有差距；不覆盖更早回合或含 steer 的多用户项回合。严格超过10,240个UTF-16单元的预切及用户composerLink已接入；sites、数学与serialized-rich-text条件尚未全部实现。Rust CommonMark parser与原包mdast实现不同，未证明所有复杂语法和孤立UTF-16代理单元等价。当前仍缺少原版语音听写与朗读；所读原包的语音和评价使用厂商接口，本地app-server没有直接等价的独立方法。用户于本次审阅明确选择暂时保留语音差距。详细边界见 [参考契约](anywork-reference-contract.md)。

## 原生兼容与限制

Codex CLI 0.163.0 已通过独立隔离会话联调，包括原地对话、引导、停止、队列、目标和计划模式。本轮另以当前0.164.0生成的command/file/permissions参数和结果六份schema复核审批结构；这项结构核对不等同于新增真实模型审批联调。原应用内置CLI版本为0.166.0-alpha.5.1。本轮通过本机生成的 schema 与隔离空会话确认当前协议使用 thread/revert，默认新会话为 paginated，legacy/ephemeral 不支持该回退；此项不发送真实模型请求。编辑端到端验证使用真实 Rust HTTP 服务和确定性 Codex 协议替身，不冒充真实模型编辑联调。共享控制使用 Unix socket；不支持共享入口、无法确认状态或存在竞争 writer 时会明确报告限制，不静默创建第二个执行引擎。

手机尺寸浏览器测试不等于 Android 真机安装验收；当前未完成实体设备安装验收。Docker/Compose 配置尚未在本机实际构建验证。DeepSeek Harness、Claude Code、Cursor 未实现生产适配器。测试结论不涵盖这些未实现或未执行的项目。

公网连通性取决于部署环境；开源仓库不附带正在运行的服务地址、令牌或可访问的私人会话。部署后应使用专门新建的隔离会话验证消息、控制、模式和附件，避免拿已有工作任务作写操作测试。
