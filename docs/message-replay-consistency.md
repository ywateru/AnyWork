# History and live replay consistency

A server-owned session stores canonical events with monotonically increasing sequence IDs. Its compact history omits `item/started` and delta events for completed items, keeping the complete item instead. The global event connection may still deliver those omitted older events after the history response has arrived. Both sources belong to the same sequence space.

Release verification exposed a completed assistant article containing the entire document answer twice. The CI trace showed a normal history response: global cursor 717, user 718, turn start 719, commentary 721, read tool 722, answer completion 725 and turn completion 726. Answer start 723 and delta 724 were absent from the compact snapshot. The response contained one copy of the answer; the rendered article contained two. The streaming response body was not captured by the trace, so deterministic tests reproduce the inferred delayed delivery explicitly.

Previously `SessionHistoryCache.read()` sorted the merged event list, while `receive()` appended missing live events. An omitted delta arriving after the compact completion was projected as full completed text followed by that same delta. Its completed event was then correctly identified as already present by sequence, leaving the duplicated text and a possible `inProgress` item status from the late start.

`receive()` now inserts missing events at their canonical sequence position for server-owned sessions. Normal new events use the existing append path. Completed text and lifecycle state therefore remain authoritative when the projector processes the sequence. Sequence identity still prevents exact replay, while distinct identical delta chunks remain valid. Events for other items below the history watermark are retained. Imported external history keeps its existing native-history reconciliation path because its identities do not share this owned-session ordering contract.

The deterministic cache regression loads compact completed history first, then delivers the missing start/delta, another item below the snapshot watermark, and the repeated completion. It checks text, item/turn completion, ordering and the concurrent item's update after each relevant delivery. Another regression verifies consecutive identical chunks, replay identity and isolation across sessions with matching item IDs. A browser fixture repeats this snapshot-first scenario through the actual history and SSE client and checks one visible document link and one answer article after a later event confirms replay delivery. The existing real fixture document-preview test keeps its strict locator.

The separate desktop-manager geometry check now waits for bundled fonts and reads the host and stop button rectangles in one synchronous DOM evaluation. It checks containment on all four sides without tolerance. The previous two protocol calls could compare different layouts during `font-display: swap`; no desktop layout CSS or service behavior changes are needed.
