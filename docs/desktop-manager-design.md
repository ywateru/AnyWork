服务启动、连接开关、状态放在同一行。配置只锁定正在运行的那一路，其他连接可继续配置并开启。地址仅在验证成功后出现。全局只有两个页面；程序位置位于服务页折叠区。

欢迎页解释桌面本地执行、网页/Android远程访问和三种连接方式。点击开始后进入服务页，无需先选择唯一网络模式。

对照需求后，放弃之前同页平铺所有配置的长表单及三个相似大卡片。连接改为分隔线列表，按需展开。字号不随窗口缩放。服务状态、连接状态和设备状态分别反映实际证据，错误保留在发生问题的那一路。

验证：Tauri 2 的 macOS 构建、Clippy 和 11 项 Rust 测试通过，包含隔离真实 Server 的鉴权、设备列表及关闭验证。三路并行、局部失败与停止、取消启动由实际测试子进程验证；公网 TLS 成功事件在该测试中模拟，不等同真实中继握手。Linux/Windows 通过 CI 配置提供构建检查，其运行结果另列。

## 实现边界

`crates/desktop` 是 Rust 管理核心和 Tauri IPC 边界，`desktop/ui` 是独立 React 界面。Web 会话客户端继续位于 `web`。Tauri 在构建时嵌入管理界面，窗口加载本地资源；Rust commands 提供指定动作、原生选取器、剪贴板和已验证地址的打开操作。管理界面没有通用 shell/fs 插件。

配置采用兼容旧版的 camelCase JSON，按系统应用数据目录存放；旧版单选隧道配置不自动开启任一路由。连接器凭据由系统 keyring 保存，访问密钥文件私有原子写入。每一路连接独立持有 Child、状态、验证任务和取消信号。只有系统 TLS 与已认证 AnyWork 服务身份都验证通过，才公布远程地址。

外部 CLI 服务只做认证连接；应用只能停止自己创建的 Server。关闭应用先停止并回收自己持有的路由和服务，再退出。窗口关闭、系统退出和 SIGTERM 都走同一关闭路径。旧 Swift 窗口与 eframe 原型已从交付源码移除。
