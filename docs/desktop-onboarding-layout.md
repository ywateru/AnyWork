# 桌面启动引导与连接控制台

日期：2026-11-10。当前用户明确要求：启动先介绍功能，再登录或注册，成功后启动服务，说明远程连接，并显示已经连接的手机或外部网页。本文是本轮交互与启动顺序的唯一契约，取代旧版“先打开工作区、账号入口并列”的首屏顺序；原有浏览器安全交接、服务所有权和内存凭据约束继续有效。

## 设计与结构

客户端承担“把这台电脑变成可访问的工作区”的引导和控制职责。采用连续的四个阶段，不把所有动作一次堆在首页。首次画面有明确的功能说明和设备关系图，完成登录后才显示实际工作区控制台。

色彩为冷白画布 `#f5f7fb`、白色工作面 `#ffffff`、正文墨蓝 `#14253d`、次要文字 `#61728a`、操作蓝 `#155ce8`、边线 `#d7e2ef`，成功文字 `#157654`。沿用随包中文字体与系统 sans；大标题 32–38px，页面标题 26px，正文 14–16px。本地地址用等宽字体。正文和动作左对齐；介绍页用一张设备关系图形成重点，控制台用行、分区和留白组织内容，避免同形卡片反复套叠。图形是关系示意，不是虚构的在线设备。

## 启动与安全交互

1. Native 启动和状态轮询允许只读探测已有服务，但介绍页、登录页不会启动服务、打开工作区或开启远程。
2. 支持账号的平台在已有原生授权确认为 signedIn 后，UI 调用新增的 `desktop_start`，只准备/核验本地服务，不打开浏览器，不签发浏览器 ticket，不开启远程。同一授权只自动提交一次；失败必须用户手动重试，不由轮询无限提交。注册成功与登录成功走同一路径。
3. Native IPC 独立核验登录状态；不能仅靠按钮隐藏来约束 `desktop_start` 和 `desktop_open`。签入状态未知、取消、授权中断、需要重新授权时均不接受新启动/打开命令。现有平台 `unsupported` 明确说明限制，不伪造登录成功或隐式绕过新引导来启动服务；CLI 仍是独立产品入口，本轮不承诺补齐上游 Windows 账号支持。
4. 启动由 manager 使用现有配置与凭据进行，先核验端口和外部服务身份；兼容且授权的已有服务复用，不换目录、不覆盖凭据、不停止外部进程。端口冲突、旧服务不支持安全交接、无凭据等错误需要明确恢复指引，不退回长期 bearer/ticket URL。
5. 本次启动命令接受时需有有效账号；已接受的启动以及已经运行的本地服务，不因后续退出账号强制终止。退出/重新授权仍关闭远程并回到账号阶段，阻止继续提交新的启动/打开命令。旧授权的迟到 UI 结果不能显示为新账号就绪或触发远程；重登录可重新核验已有服务。
6. “打开本地工作区”仍使用一次性交接与 HttpOnly Cookie。显示/复制地址仅来自已保存 snapshot 的合法端口，复制裸根地址。首次、切换浏览器和会话过期时点击打开按钮。手机不能用 `127.0.0.1`；远程指引必须提供正式账号入口的裸 HTTPS 地址，不包含令牌、设备私钥或一次性授权参数。
7. 登录不自动开启远程；用户明确允许后才发布设备。首次连接或换钥继续核对本机身份。不能新建 Keychain、Native 持久秘密或云端业务内容存储。

## 已连接设备的真实边界

以 Native 的加密 gateway 中“已验证账号并完成握手的活动连接”为真源，不把 Logto 设备目录的注册设备、manager `/api/clients` 的历史心跳或本地浏览器算成当前远程连接。

gateway 在握手时从 WebSocket User-Agent **只推导有限的设备类别**，如 iPhone/iPad、Android、桌面浏览器、未知网页；不保存原始 UA、IP、请求正文、账号 token 或完整公钥用于显示。该类别是用户端可声明的提示，不是可信设备身份或新的权限依据；无法识别时明确显示“网页客户端”，不假装知道设备型号。无需改变 Noise 握手协议或云端目录格式。

握手验证成功后注册 RAM-only 连接，连接结束、JWT 到期、失效续期、注销或关闭远程时移除。续期保留相同连接编号和开始时间，不重复计数。快照返回有限的显示字段：`id`（连接临时编号）、`kind`（`ios` / `android` / `desktop` / `unknown`）、`connectedAt`（Unix 秒），不输出原始 UA/IP/用户 subject/密钥或凭据。UI 显示“已连接”和开始时间/已连接时长，来源未知与真实 0 个连接不能混淆；账号快照不可用时显示“连接状态暂不可用”，不能伪装空列表。最多受 gateway 现有 4 个 socket 上限约束。

该功能表示活动加密连接，不承诺物理设备唯一去重、远程屏幕内容监视或可用的后台推送；同一手机开两个独立连接可以显示两行。关闭远程后连接区明确为已关闭，不继续显示旧连接。

## 验证与交付

分为 UI 作者、Native 作者和独立审查三个角色。隔离验证覆盖：介绍前无启动调用、登录成功到只启动服务的真实 IPC/manager 链、未登录的 Native 命令拒绝、失败重试/取消/重新登录竞态、已有外部服务复用且不停止；活动连接只在真实授权握手后出现，续期不重复、断开/过期/禁用移除、仅返回有限类别。UI 在四种尺寸检查介绍、登录、准备、就绪、连接列表、错误、设置和更新状态。

使用合成账户/隔离服务验证代码；不自动登录真实用户、不启用用户远程、不打开真实会话正文。实际本机安装仍需独立核对候选产物，并保留现有服务的进程、路径、inode、环境、配置和凭据。用户先前已授权发布，新流程通过审查与检查后再按不可变发布流程发版；当前 `b782919` 的 `0.1.16` 发布器在 tag 前已停止，继续发布必须包含本轮完整变更，不让旧候选自动发布。
