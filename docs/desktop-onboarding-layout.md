## 设计与结构

客户端承担“把这台电脑变成可访问的工作区”的引导和控制职责。采用连续的四个阶段，不把所有动作一次堆在首页。首次画面有明确的功能说明和设备关系图，完成登录后才显示实际工作区控制台。

色彩为冷白画布 `#f5f7fb`、白色工作面 `#ffffff`、正文墨蓝 `#14253d`、次要文字 `#61728a`、操作蓝 `#155ce8`、边线 `#d7e2ef`，成功文字 `#157654`。沿用随包中文字体与系统 sans；大标题 32–38px，页面标题 26px，正文 14–16px。本地地址用等宽字体。正文和动作左对齐；介绍页用一张设备关系图形成重点，控制台用行、分区和留白组织内容，避免同形卡片反复套叠。图形是关系示意，不是虚构的在线设备。

## 启动与安全交互

1. Native 启动和状态轮询允许只读探测已有服务，但介绍页、登录页不会启动服务、打开工作区或开启远程。
2. 支持账号的平台在已有原生授权确认为 signedIn 后，UI 调用 `desktop_start`，只准备/核验本地服务，不打开浏览器，不签发浏览器 ticket。同一授权只自动准备一次；失败必须用户手动重试，不由轮询无限提交。注册成功与登录成功走同一路径。本地准备成功后，另行提交默认远程操作；远程尚未就绪或失败不阻塞本地就绪、打开工作区和设置。
3. Native IPC 独立核验登录状态；不能仅靠按钮隐藏来约束 `desktop_start` 和 `desktop_open`。签入状态未知、取消、授权中断、需要重新授权时均不接受新启动/打开命令。现有平台 `unsupported` 明确说明限制，不伪造登录成功或隐式绕过新引导来启动服务；CLI 仍是独立产品入口，本轮不承诺补齐上游 Windows 账号支持。
4. 启动由 manager 使用现有配置与凭据进行，先核验端口和外部服务身份；兼容且授权的已有服务复用，不换目录、不覆盖凭据、不停止外部进程。端口冲突、旧服务不支持安全交接、无凭据等错误需要明确恢复指引，不退回长期 bearer/ticket URL。
5. 本次启动命令接受时需有有效账号；已接受的启动以及已经运行的本地服务，不因后续退出账号强制终止。退出/重新授权仍关闭远程并回到账号阶段，阻止继续提交新的启动/打开命令。旧授权的迟到 UI 结果不能显示为新账号就绪或触发远程；重登录可重新核验已有服务。
6. “打开本地工作区”仍使用一次性交接与 HttpOnly Cookie。显示/复制地址仅来自已保存 snapshot 的合法端口，复制裸根地址。首次、切换浏览器和会话过期时点击打开按钮。手机不能用 `127.0.0.1`；远程指引读取 `account_snapshot.accountPortalUrl`，它与 Native `Handle::portal_url()` 及 `desktop_account_portal` 使用相同的公开绑定，不能在 UI 硬编码域名覆盖未来自部署配置。该值必须是无凭据、query、fragment 的裸 HTTPS 地址；缺失/非法时显示暂不可用并禁用复制，不凭空生成默认。地址不包含令牌、设备私钥或一次性授权参数。
7. 每次新的有效登录授权，在本地服务核验成功后默认尝试开启远程一次。介绍或登录页面用一句话说明默认开启、可随时关闭。默认尝试失败后显示精简错误和显式重试，不靠轮询反复发布设备；错误代码和进一步诊断放在展开的详情中。手动关闭后，本次 Native 登录会话保持关闭，UI 重载、轮询恢复、设置往返、再次准备服务不得重新打开；退出再登录或客户端重启后的新登录重新采用默认开启策略。该默认尝试和手动关闭意图由 Native RAM 内的当前 grant 所有者保存，不能仅依赖 React 内存。新增 `account_enable_default` 命令消费本次授权的默认尝试；无账号时拒绝，已消费/已手动关闭/已开启时按契约幂等不操作。显式 `account_enable` 用于用户重试或重新开启；关闭/退出与迟到的默认开启结果必须有 Native 隔离，不能在关闭后重新发布。首次连接或换钥继续核对本机身份。不能新建 Keychain、Native 持久秘密或云端业务内容存储。
8. 更新后重启也进入新的介绍/登录阶段；磁盘上的旧 `resume.json` 不得在启动时执行服务启动。保留旧文件不执行即可，不把其存在当登录。新登录后的 `desktop_start` 使用已有 manager 配置安全准备服务，无需新的磁盘启动授权。安装失败但当前进程仍在时，可以恢复本次安装前已由 manager 管理且已获准运行的同一服务；这是原已接受工作的恢复，不得启动独立外部服务或恢复远程。安装仍需原有显式确认和空闲检查。

## 已连接设备的真实边界

以 Native 的加密 gateway 中“已验证账号并完成握手的活动连接”为真源，不把 Logto 设备目录的注册设备、manager `/api/clients` 的历史心跳或本地浏览器算成当前远程连接。

gateway 在握手时从 WebSocket User-Agent **只推导有限的设备类别**，如 iPhone/iPad、Android、桌面浏览器、未知网页；不保存原始 UA、IP、请求正文、账号 token 或完整公钥用于显示。该类别是用户端可声明的提示，不是可信设备身份或新的权限依据；无法识别时明确显示“网页客户端”，不假装知道设备型号。无需改变 Noise 握手协议或云端目录格式。

握手验证成功后注册 RAM-only 连接，连接结束、JWT 到期、失效续期、注销或关闭远程时移除。续期保留相同连接编号和开始时间，不重复计数。快照返回有限的显示字段：`id`（连接临时编号）、`kind`（`ios` / `android` / `desktop` / `unknown`）、`connectedAt`（Unix 秒），不输出原始 UA/IP/用户 subject/密钥或凭据。UI 显示“已连接”和开始时间/已连接时长，来源未知与真实 0 个连接不能混淆；账号快照不可用时显示“连接状态暂不可用”，不能伪装空列表。最多受 gateway 现有 4 个 socket 上限约束。

该功能表示活动加密连接，不承诺物理设备唯一去重、远程屏幕内容监视或可用的后台推送；同一手机开两个独立连接可以显示两行。关闭远程后连接区明确为已关闭，不继续显示旧连接。

## 验证与交付

本轮任务见 [默认远程与精简控制台](plan/tasks/desktop-default-remote.md)。Native、UI 作者各自实现并提交，独立审查者检查精确提交与合并集成。覆盖登录→服务就绪→默认远程、失败不阻塞本地、显式重试、手动关闭后 UI 重载/重复准备不重开、关闭/退出与迟到默认操作隔离、新登录重新默认开启。协调配置故障需记录实际接口和传输证据，不放宽 issuer/resource/client_id 校验，不仅增加重试掩盖根因。

控制台默认收起连接列表、身份核对和连接说明；设置中的连接与隐私说明可按需展开。连接状态未知、零连接和远程关闭仍须区分，不能通过折叠丢失真实数据。错误首屏为简短说明与重试，代码放详情。四种尺寸验证主操作、键盘展开、设置返回和错误状态；测试不依赖真实用户数据。

使用合成账户/隔离服务验证，不自动登录真实用户、不启用用户远程、不打开真实会话正文。现有本机客户端和服务保持运行。用户先前已授权发布；审查与合并检查通过后按不可变发布流程发版，不移动已发布 v0.1.24 标签。本机安装另行核对候选产物，保留现有服务及凭据。
