# AnyWork 会话界面

AnyWork 将本机 Agent 的会话带到桌面和手机浏览器，目标是任何时候、任何地方都能完成工作。本轮重构以 Codex 桌面应用的会话区域为参考：消息、工作过程、输入框、审批、图片与文档、分屏共同构成一套工作界面。现有 Android 宿主继续保留，本轮交付和验证范围为 Web。

## 布局与视觉

桌面侧栏负责切换会话。按工作目录分组时，每组取当前视图中最新会话的 updated_at，目录组按该时间倒序排列，组内会话也按 updated_at 倒序；归档会话只影响归档视图，时间相同时用路径/会话 ID 稳定排序。主区域的 43px 顶栏显示当前会话的对话、文档与工具子窗口；每个会话有自己的标签组，不再把多个会话放进同一组标签。对话标签显示会话标题，始终保留；文档按规范化绝对路径去重，变更、目标、终端各自保持一个入口。加号打开当前会话的子窗口工具，不创建另一个会话。标签及选中项按服务器与会话共同保存，支持方向键、Home/End、Delete 和关闭。桌面子窗口与对话分屏，右侧顶栏显示当前子窗口名称；手机覆盖面板仍保留顶部标签入口。关闭子窗口不归档会话，也不停止 Agent 任务，终端面板卸载会按既有规则断开其 PTY。具体状态及原版静态证据见[会话子窗口与浮层契约](conversation-panels.md)。

会话内容居中，桌面正文宽度上限 768px、左右基础留白16px。默认外观为中性色 Codex 主题，系统字体14px、代码12px、正文行高1.625。浅色用户气泡接近 `#f3f3f3`、主文字 `#0d0d0d`；用户消息右对齐，桌面最大宽70%、圆角22px。助手正文直接排版，无头像列或重复角色名称。外观设置继续支持浅色、深色、跟随系统、主题预设与字体/颜色调整，既有偏好保留。

工作活动采用无背景的紧凑行，普通块间隔16px、组内4px；摘要来自协议动作与状态，展开才读取大型结果。已完成轮次把中间说明和工具活动合并到“用时”入口，最终回复留在正文；历史无时间时回退为先前消息数量。展开状态按会话保留，错误和最终回复之后的活动保持可见。独立 reasoning 条目当前不呈现，这是实现范围，不能据此认定原版没有思考过程。

## 回复操作

用户正文先按原生 input 处理辅助图片说明、经过严格 schema 校验的 app-input 与 library 文件提及，再进行请求包装提取。普通路径提取两次；首个有效 app-input 含 message 时只执行共享显示层的一次提取。服务端的 display_text 已是最终正文，浏览器不再二次裁剪；旧事件保留普通兼容规则。原始事件与 input 独立保留，实时回显只在同回合首文本唯一匹配时补充显示内容。应用和 library 消息可进入同一历史编辑流程，提交后按原版清除首文本元数据。普通历史编辑已接入独立的 ProseMirror PZ 文档与 mention URI 规范化；主输入框及富文本历史模式仍待实现。发送者、自动化等特化路径仍未完整复刻。

Library 行内提及仅识别通过原生展示语法校验的 Google Drive、Box、Dropbox、SharePoint 和 OneDrive 文件来源。使用 16px 图标槽、3px 尾间距、medium 字重、可换行标签与 hover 虚线下划线；保留原始 prompt-link 元数据，实际链接指向 sourceUrl。Web 在浏览器新标签打开，不模拟桌面内置浏览器窗口；23 个常见静态图标已接入，少见 MIME 与 Figma/泛 Office 特化图标仍有差距。

用户 Markdown 专属 composerLink 扩展按原包扫描带空格的路径、标点转义和格式化标签。标准非空标题交给基础语法，代码、图片、嵌套链接保留各自的解析作用域；未完成链接保持当前行字面量。codex-text-link 前缀按原包规则在用户源字符串中规范化；助手消息保持原解析。sites 扩展仍未接入。

用户正文保留 Markdown 标题、强调、列表和代码；其中图片语法按原包用户分支显示为感叹号与标签链接，上传附件另行展示。相邻段落间距20px，保留段落内部换行。未超过10,240个 UTF-16 单元时按实际视觉行测量，超过20行折叠为19行与独立省略号，跨越边界的代码块保留完整。严格超过10,240个 UTF-16 单元时，折叠态先渲染 `text.slice(0,10240)`，强制折叠并限制为19行与省略号，跳过全文测量和跨代码块增高；不修补单词、Markdown 或代理对边界。展开与打印恢复全文。

用户气泡下方提供复制，优先同时写入渲染后的纯文本与HTML，复制折叠消息时包含全文；预切消息在取复制快照时同步临时挂载完整正文，读取后恢复折叠态。成功反馈持续1.5秒，失败可以重试。桌面悬停或键盘聚焦显示操作，无悬停设备常显复制；时间仍只在悬停或聚焦时显示。消息时间仅采用真实消息时间；导入历史的索引更新时间不能代替它。居中日期分隔依据真实回合/消息时间及原包时间间隔规则生成，与气泡下方时间分开处理。只有服务端确认具备编辑能力的最新用户消息才显示“编辑消息”：要求 Codex 原生持久化 paginated 会话空闲、最新回合仅一条 userMessage，且显示项与原生输入匹配。更早回合、多条用户输入或执行中的回合不提供编辑入口。

编辑时以可增长文字输入区替换气泡，自动聚焦，显示“取消 / 发送”；初值是提取后的正文，原有附件保留并可查看。普通 UI 从文档取得规范化文本后执行 `trim()`；核对结果时保留已提交稿原文。API 重建首 text 的 Ooe 对应逻辑本身不 trim，它在原输入上保留或重建上下文前缀。发送期间禁用重复提交和取消；Escape 只在没有输入法组合或其他弹层时取消。普通历史编辑使用 paragraph/code_block、link mark 与 16 类原子引用的 PZ schema；保留真实选区、撤销重做与中文输入保护。桌面 Enter 提交、手机普通 Enter 换段；Shift/Alt+Enter 换行，代码块 Mod+Enter 移到后续段落。Android Chrome 的修饰回车由 Web 适配层补齐。复制使用 schema HTML 与独立 KX 剪贴板文本，支持原生 library/richLink/atMention/resource DOM 属性恢复。library 编辑态采用 20px 图标与 selection-pill 布局，长文件名按字形测量后中间截断且保留完整复制标题。主输入框的 rich schema、完整引用动作菜单和所有 HTML 归一分支仍有差距。

编辑在同一原生 thread 先 revert，再发送保留原附件的新输入。服务端确认回退后刷新会话历史；即使原消息从历史消失，独立恢复编辑区仍保留失败草稿与错误。成功才退出编辑。已提交操作和阶段保存在服务端，刷新或切换回来会恢复未完成操作；尚未提交的编辑草稿及上次提交后未再次保存的修改不承诺跨刷新恢复。重试沿用同一个操作标识，先核对真实历史；上次发送结果未知时不自动再发。

结果待确认的 uncertain、starting、reverting 阶段保持提交文字只读，仍可选取复制，并提供“核对发送结果”和取消。核对使用同一操作及原文字；若服务端完成结果中的文字与当前草稿不同，保留草稿并明确提示，不静默关闭编辑区。

取消提交过的编辑只结束本地恢复操作，不恢复已经回退的历史，也不撤销文件改动；原消息已被回退后，取消可能留下仅包含更早回合的会话。编辑会暂停待发送队列，完成或取消后仍保持暂停。AnyWork 的会话锁与指纹复查不能阻止原生客户端在检查和变更之间同时操作，没有原子 CAS 保证。

助手回答下方按参考截图排列复制、组合赞踩评价、朗读和更多入口。复制读取已渲染的正文文本，更多菜单可复制原始 Markdown 或下载回答。反馈菜单与详情窗参照原包结构，使用本地保存说明；评分按会话和消息 ID 保存，可编辑与移除，重启恢复并随会话导出。此能力不调用厂商评价或诊断上传接口。朗读入口明确说明当前版本尚未提供此能力，不播放模拟音频。

## 输入、审批与目标

输入框为一体布局，圆角22px，包含附件、可增长文本区和底部工具行。左侧为添加与权限盾牌，右侧为模型/思考强度与发送/停止。桌面普通控制按钮28px。运行且没有草稿或附件时显示停止；有补充内容时显示发送，运行中的默认发送直接排队；关闭排队后默认引导，Mod+Enter 临时切换发送方式。排队列表位于目标栏上方，与输入框共用上方区域；两侧内缩13px，行高至少32px，圆角16px。行内提供引导、删除及三点菜单，菜单只含编辑消息和关闭/开启排队。关闭排队只保存后续发送偏好，不清除、暂停或立即投递已有条目。

编辑排队消息先从列表移出，再把完整文字和图片/文件附件恢复到主输入框并聚焦；没有行内编辑框。原主草稿可通过撤销恢复，排队消息回到原FIFO位置。等待移除时若用户继续改稿或切换会话，恢复原排队消息并保留新草稿。服务端保存独立编辑事务，刷新和重启后仍可恢复；重新提交替换原队列位置。该实现覆盖 AnyWork 的文字和附件，没有覆盖原版所有上下文字段与完整应用撤销/重做栈。

`ComposerAdd` 提供上传文件、添加远程文件、目标和计划模式。目标创建复用主输入框，底部添加 Target 图标与“目标”标记，不弹出独立输入框；取消标记保留富文本与附件。允许仅图片的目标，发送消息被接收后再启用持久目标；排队中保存模式，实际投递才生效，编辑/撤销和刷新恢复各自模式。远程文件从当前会话目录浏览并引用原文件；上传图片立即显示本地预览，完成前禁止提交。`GoalBanner` 在输入框上方显示真实目标状态，支持删除、暂停/恢复和展开详情；已完成目标隐藏，运行中每秒更新累计耗时，有可用token预算时显示预算进度。目标创建按原版发送 `/goal` 输入，再调用 Codex 原生 goal 接口；详情编辑只更新原生目标状态。计划模式更新协作设置。目标创建与侧栏边界见 [目标契约](anywork-goal-editor-contract.md)。

`ModelPicker` 把模型名称、思考强度和箭头放在同一触发器中，菜单从服务端读取实际可用模型与强度。有至少两档有效强度时显示原生显式模型分支的滑杆；点击标题进入模型列表，选择后返回强度；列表只显示分组标题及选项，隐藏速度入口。滑杆下不常驻强度说明，保持原版 simple 页结构。拖动、触屏、方向键及聚焦后的滚轮调整会保存到引擎；滚轮累计30px换一档，160ms无事件或方向改变后重新累计；请求顺序执行并合并尚未提交的中间选择，最终保存用户最后选择的档位。Enter 关闭并返回焦点。连接原执行入口后主动重读设置，任务状态改变后再次刷新；同一会话从历史模式连接到原 owner 后无需切换会话即可选择。原接口允许执行中单独更新思考强度，滑杆保持可用并保存到原线程；模型、服务等级和计划模式仍需空闲。无法连接原 owner 或已归档时保持只读，并显示具体原因。

速度入口独立于强度，从模型实际公布且通过权限过滤的 `serviceTiers` 生成。只有一个快速档位时使用闪电开关，其他目录使用233px浮层，包含显式空值“标准”和实际档位，不虚构未公布的默认 ID。切换至不支持当前速度的模型时同时清除覆盖；原生拒绝保存会保留原值并显示错误。没有真实动态 preset 来源时不添加“默认／推荐模型集”；账号锁定等其余条件分支仍属于未知范围。

待处理审批和问答固定在输入框上方的请求区，避免被历史滚动带走。审批明确显示请求的命令、目录和权限；命令/文件请求提供“允许一次”，permissions 请求显示“允许一次”，并注明“本回合有效”，与实际 `scope:turn` 一致。原因只将 HTTP(S) 地址转成外链。长详情独立滚动，底部按钮保持可见；问答保留选项及自由输入，协议显式允许时支持多选。卡片宽度小于28rem时动作纵向排列；单张待处理审批支持 Enter 批准和 Escape 拒绝；输入、输入法、菜单/弹窗、多张待处理卡和重复按键均有保护。可用动作来自请求及其明确决定列表：文件可选“允许所有修改”，网络可选“允许此对话”和原提案“始终允许”，普通命令有原前缀提案时可选“允许类似命令”；权限请求可授予本回合或本对话。scope动作通过“审批选项”split-button展开，网络持久规则为独立按钮。服务端逐项校验原生结果，不通过全局自动审批模拟这些范围；明确空决定列表不能回退为允许。请求解决、执行结束或断线后不能重复回应旧请求。

文字草稿由 `useSessionDraft` 按服务器与会话隔离，保存在当前标签页的 `sessionStorage`，刷新和切换会话可以恢复；存储不可用时回退内存。该保证适用于文字，不表示未上传附件可以跨刷新恢复。

## 图片、文档与分屏

输入图片可以点击或按键打开查看器，保留草稿，关闭后返回缩略图焦点。历史图片与 imageView 活动按需读取；支持多图浏览、适应窗口、缩放、拖动与 Esc 关闭。图片经带鉴权请求转为临时 Blob 地址，令牌不放入 URL，失效资源及时回收。

会话中的本地文件链接在右侧打开，保留会话和草稿。`Workspace` 提供文件树、Markdown 渲染、源文本、锚点/代码行定位、编辑与 Git 差异；预览标签允许在已打开文件间切换。`DocumentPreview` 先鉴权获取二进制文件，再用 Blob URL 内嵌 PDF iframe；Office/OpenDocument 显示下载入口，由用户的文档应用打开。没有在线 Office 渲染服务。快速切换文件会取消旧请求并忽略迟到响应。

`SplitPane` 用容器 ResizeObserver 计算可分配宽度，左右至少160px。分隔线可见宽1px、覆盖式交互宽12px，不额外挤占正文；支持鼠标/触控拖动、方向键每次10px、Home/End 到边界、双击恢复默认比例。左侧宽度按服务器保存到本地，容器变小时重新钳位。会话在打开面板期间持续挂载。

视口不超过720px时，文件、变更或终端面板覆盖整个主内容区；隐藏会话视觉并保留其状态，关闭面板返回会话，隐藏拖动条。手机输入字号16px、尊重底部安全区，会话顶栏紧凑显示。此满宽覆盖是 AnyWork 的移动实现选择；原包 split-view 默认90%抽屉不能当作已观察到的手机截图行为。
