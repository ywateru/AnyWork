# Dormant qualified SDK transport (I07b1-A)

Status: implementation candidate, not independently accepted. The [lifecycle contract](runtime-lifecycle.md) remains authoritative. Only `crates/agent-sdk` is implemented here; production Runtime/server/adapters/Store/Web do not consume this API. Native-positive capability actions remain denied. Full B/C, durable preparation/creation, native writing and platform acceptance remain open.

## Selected API and authority

`remote_agent_sdk::qualified` is a separate opt-in Rust module. `Transport::open(Endpoint, Limits)` returns a transport, bounded metadata receiver and bounded native-event receiver. Endpoint is `Owned(PluginManifest)`, Unix-only `Unix(PathBuf)` or `LegacyBridge`. **LegacyBridge returns `UnsupportedBridge` without enqueuing anything.** There is no qualified-to-raw conversion/fallback or optional qualifier for old consumers to ignore. Existing `RpcProcess` and its bridge stay unchanged.

`Qualification::new(Binding, Arc<dyn Admission>)` requires a caller-supplied authority; there is no default/always-true production validator. Binding is an immutable opaque 32-byte caller identifier. `Admission::admit(&Binding)` is a synchronous final ordering callback: the future server manager checks its CommitCell/current runtime+peer+occurrence and records admission there. It must not block on network, reenter the SDK or interpret the payload as authority. SDK admission is serialized with SDK close/cancellation; the callback executes in the actual writer, after outbound queueing and immediately before that writer's bounded write. The manager must not hold its CommitCell while entering SDK methods. This carries authority, not a second runtime registry or preparation journal.

`send(qualification, value, deadline: Instant)` returns only `LocalWrite`, never native acceptance. `call(qualification, method, params, deadline)` returns `Reply` with the native result; a generic native error becomes typed `NativeError/Unknown`. Deadlines use monotonic `Instant` and include queue/write/reply waits. No wall-clock or incoming frame creates freshness. Every request has immutable qualification and one attempt; no retarget/retry.

`Failure` has a controlled `Kind` and `Disposition::{NotAdmitted, Unknown}`. Queue/size/pending limits and authority refusal before final admission are NotAdmitted. Once admitted, partial writes, deadline/cancellation, closure, parse/transport failure and generic native errors are Unknown. Local write completion and matching RPC reply are distinct metadata phases, not proof of semantic native acceptance. The final-admission point precedes asynchronous wire execution; bytes may or may not reach the peer after an admission ordered before close.

## Bounds, cancellation and terminal ownership

Defaults: metadata 128 outstanding receipts, 2 KiB/item, 256 KiB aggregate; outbound 16 outstanding envelopes, 32 MiB/item, 64 MiB aggregate; native events/replies 128 outstanding frames, 32 MiB/item, 64 MiB aggregate; pending registrations 128. Limits may be lowered for deterministic tests, never raised past these maxima. Actual encoded JSON byte counts are enforced. Outbound serialization writes through an item-limited sink. Stdio reads at most item-limit plus one byte before JSON parsing (with an independently bounded ≤8 KiB read buffer); an unterminated oversized line closes without waiting for a newline or EOF. Unix WebSocket frame and assembled-message limits are configured before reception/parsing, rather than accepting the library default and rejecting an already parsed object. Encoded-byte budgets bound retained wire data, not the allocator overhead of a parsed JSON tree. Legacy raw reads are deliberately unchanged; I06 remains open. Received wrapper values retain their reservations until dropped; dropping a queue releases queued reservations. Payloads are never put in metadata. Metadata fields are fixed typed phases, binding, request number and monotonic elapsed duration. Terminal reasons use a separate controlled enum, never a provider error object. The synchronous authority callback must be short and nonblocking; the SDK cannot safely preempt arbitrary caller code while preserving an atomic admission ordering point.

Metadata overflow/receiver loss and native-frame overflow fail closed through a sticky terminal state and watch notification independent of draining any queue. Closure is never an ordinary queued metadata frame that can be dropped. Old transport state cannot be reopened. Receivers can drain previously retained packets and then return `None` on terminal even while the transport owner remains alive; terminal wakeup does not depend on sender destruction. No new metadata/event packet is published after terminal. Late RPC replies do not resurrect canceled waiters. Caller future drop synchronously removes its registration; cancellation is projected as NotAdmitted or Unknown from the actual admission state. An undrained canceled outbound envelope may occupy its bounded reservation until the writer discards it or close drops its queue; it cannot write or replay. Queue submission uses bounded nonblocking admission, not an unbounded task per sender.

The resource supervisor owns the child/transport tasks. Explicit close and last transport-owner drop set terminal first, stop SDK writer/reader tasks and detach external sockets. Owned children retain kill-on-drop, are killed and waited/reaped; explicit close returns the observed resource outcome. Cleanup uses one five-second budget covering task quiescence and child reap. `CleanupUnknown` is observable when that budget expires; the supervisor retains its task/process handles and continues waiting, so callers must not treat that outcome as quiesced or activate a competing writer. A later confirmed cleanup can become Reaped/Detached. Last-owner drop performs the same teardown even when neither bounded receipt queue is drained. External close never signals/kills the fake or real host process. Legacy transcript paths do not become this module's observation backlog.

No staged dead-code suppression or artificial server call is needed: this is a public-to-SDK opt-in module used by isolated tests. B/C must replace installed Runtime raw handles, provide a real admission authority, qualify every setup/event/adapter effect, bind pending occurrences and consume terminal/metadata state. The unmigrated bridge needs an independently designed mandatory final-adapter seam before it can be enabled; this module deliberately rejects it.

The first all-targets compile failed only because this worktree lacked `desktop/ui/dist` required by Tauri's `generate_context!`. A read-only copy of the already existing root desktop dist was placed in this tree's ignored dist solely as a compile fixture, then all-targets compilation succeeded. This is not a new desktop UI build or UI acceptance result. No root build output was written.

Wire and ownership assertions include:

- Actual serialized stdio writer: first frame is blocked after admission, a second immutable binding is queued, then revoked. Exact wire data is only the first frame; the second and later reuse are NotAdmitted with no retarget. Queued cancellation and expired deadlines have zero additional wire effect and release registrations/reservations.
- Actual Unix WebSocket writer and fake Unix listener: a 16 MiB first frame is under socket backpressure while a second frame waits. Revocation happens before releasing the host read barrier. Exactly one frame arrives; the queued second frame is refused before admission, with no retry. Test host limits explicitly allow that large fixture frame.
- Input bounds before parsing: 33 bytes without newline at a 32-byte stdio limit close while the producer stays open; a Unix frame header advertising 33 bytes at a 32-byte limit closes without the host providing a body. No event or retained incoming reservation is produced.
- Actual owned Python fixture: echo and generic native rejection, admitted-call cancellation/deadline, EOF, and 4096-byte partial pipe receipt followed by process exit. Partial write is Unknown; explicit/repeated close reaps. A separate last-owner-drop case observes Reaped without draining receipts. The external Python Unix host survives two detach/reconnect cycles and is killed/reaped only by test cleanup.
- Independent count/item/aggregate receipt bounds, encoded Unicode item size, pending cap, independent outbound count and aggregate limits, incoming count/aggregate limits including held packets, and release-on-drop. Full metadata queues cannot hide EOF, writer failure, explicit close, or response-receipt overflow; that overflow cannot escape as success. Authority panic fails closed before wire admission without poisoning cleanup. A started non-abortable fake task proves CleanupUnknown retains the supervisor until a barrier allows quiescence.

No server/runtime/adapter code or capability projection changes. No native account, real application process, production service, message, publication or credential was accessed. Windows/Linux native execution, real agent interoperability, the complete connected B/C lifecycle, same-Arc reconnection, durable preparation/restart fencing and I06's legacy input/caches remain unverified or unimplemented here. The new opt-in API is intentionally dormant; no current runtime becomes safe merely because these module tests pass.
